# The chat assistant

Adding a tool is a procedure — the `add-assistant-tool` skill has it.

- `src/lib/assistant/` — the chat assistant: an LLM that manages learner state through **tool calls** (the app's own miniature MCP), UI at `src/routes/chat/+page.svelte` (ephemeral history by design). `tools/` is another registry in the house pattern — one module per tool (`add_words`, `list_words`, `update_word`, `remove_word`) bundling its zod `paramsSchema` and `run`, with `tools/index.ts` projecting the client tool JSON (`toolDefsForClient`) and dispatching `executeToolCall`; **adding a capability is one def module + one registration** (the `add-assistant-tool` skill has the contracts). Tools run against an injectable `ToolContext` whose default is wired to `$lib/db` + `$lib/srs` in `tools/context.ts` — the only module here that touches the DB — so every mutation goes through the repositories and therefore captures sync events for free; `add_words` initializes FSRS cards and dedupes by term key — and since lesson generation writes challenges only, it is the **one** route by which vocabulary enters the collection, so that dedupe is the only thing standing between the learner and a forked SRS history. `chat.ts` owns the loop (`sendChatMessage`: system prompt from profile + word count, at most `MAX_TOOL_ROUNDS` rounds, tool failures fed back to the model as `{error}` results rather than thrown; only `LlmError` escapes). A turn is atomic: tool traffic is never replayed into later turns — prior turns travel as prose. Mock mode (`mock.ts`) parses `term = meaning` lines and drives the *real* executors, so the offline path exercises real code.

- `src/lib/conversation/` — **conversation mode**: the same seam, a different job. A role-played dialogue with an LLM teacher, UI at `src/routes/converse/+page.svelte` (ephemeral too — the transcript lives in `$state`, only vocabulary survives a session). It reuses the assistant's `ToolContext`, `executeToolCall` and `add_words` **verbatim** and imports nothing from `$lib/db`; `add_words` is the *only* tool exposed (`list_words` would be a paid round trip for a list already in the prompt, and a role-play teacher has no business deleting vocabulary), and it is called only for a word the *learner* produced correctly. Two envelopes are pinned with `responseFormat` and re-parsed with zod (`schemas.ts`, `.nullish()` normalized to absent): the one-off scenario call (`scenario.ts` — setting/roles in the native language, so the setup is understood before immersion starts) and the per-turn teacher reply (`teacher.ts`). **Corrections never enter the spoken line**: `correction.corrected` is the learner's whole message rewritten — a `{text, reading}` line, not a string — and `diff.ts` derives the inline spans by aligning it against what was typed. **A learner with no keyboard for the target script types the reading**, so romanized input is declared legitimate in the prompt, `alignedForm` diffs against `corrected.reading` rather than the script when what they typed is Latin, and that comparison alone is loosened — tone marks folded, case ignored, and syllable spacing ignored as a whole-message test (`sameRomanization`), so a message that was right but spaced differently draws no correction. **The loosening is scoped to the reading and must stay there**: in the language's own spelling every mark counts, and French `ecole` for `école` *is* the correction. `teacher.ts` mirrors `chat.ts` — atomic turn, tool failures fed back as `{error}`, only `LlmError` escapes — with two deliberate differences: `MAX_TOOL_ROUNDS = 2` **and the last round is asked without `tools`** — one tool needs no read-then-write, and a model that spends the final round on a tool call would end the turn with a tool result nobody asked about and no line for the learner; and history replays as *dialogue*, learner turns as what was actually typed rather than the corrected version. A turn that will not parse degrades to prose rather than breaking the conversation; a scene that will not parse throws, because there is nothing to play without roles. Design doc: `docs/conversation-mode.md`.
