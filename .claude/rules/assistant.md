# The chat assistant

Adding a tool is a procedure — the `add-assistant-tool` skill has it.

- `src/lib/assistant/` — the chat assistant: an LLM that manages learner state through **tool calls** (the app's own miniature MCP), UI at `src/routes/chat/+page.svelte` (ephemeral history by design). `tools/` is another registry in the house pattern — one module per tool (`add_words`, `list_words`, `update_word`, `remove_word`) bundling its zod `paramsSchema` and `run`, with `tools/index.ts` projecting the client tool JSON (`toolDefsForClient`) and dispatching `executeToolCall`; **adding a capability is one def module + one registration** (the `add-assistant-tool` skill has the contracts). Tools run against an injectable `ToolContext` whose default is wired to `$lib/db` + `$lib/srs` in `tools/context.ts` — the only module here that touches the DB — so every mutation goes through the repositories and therefore captures sync events for free; `add_words` initializes FSRS cards and dedupes by **card**, not by spelling (`sameCard` in `$lib/text`: same `termKey` *and* a reading that fails to tell the two apart) — so 长 `cháng` and 长 `zhǎng` are two words with two schedules, while a word offered with **no** romanization still collides with every spelling of itself, and so does an existing card stored without one. That asymmetry is the back-compat rule: there is nothing in a bare 长 to say which 长 it is, and a careless model call must not be able to fork an SRS history on a guess. Since lesson generation writes challenges only, `add_words` is the **one** route by which vocabulary enters the collection, so that dedupe is the only thing standing between the learner and a forked history. `update_word` enforces the same rule on the way out (an edit that would land one card on top of another is refused), and both it and `remove_word` take an optional top-level `romanization` to say *which* homograph they mean — an ambiguous term is a readable failure, never a guess, because `remove_word` cannot be undone. `chat.ts` owns the loop (`sendChatMessage`: system prompt from profile + word count, at most `MAX_TOOL_ROUNDS` rounds, tool failures fed back to the model as `{error}` results rather than thrown; only `LlmError` escapes). A turn is atomic: tool traffic is never replayed into later turns — prior turns travel as prose. Mock mode (`mock.ts`) parses `term = meaning` lines and drives the *real* executors, so the offline path exercises real code.

- `src/lib/conversation/` — **conversation mode**: the same seam, a different job. A role-played dialogue with an LLM teacher, UI at `src/routes/converse/` — the library and start screen at `+page.svelte`, one resumable transcript at `[id]/+page.svelte`. **Persisted the way reading mode persists texts** (`conversationStarted`, `turnAdded`, `conversationDeleted`; `docs/conversation-mode.md` §6a): the log is append-only and so is a conversation, so nothing is ever edited and the whole feature costs three insert-or-ignore rules. **The unit of persistence is the exchange** — a learner message and the teacher turn that answered it, written together, so a message whose reply failed is never stored and history always ends on a teacher line, which is what `runTurn`'s dialogue replay resumes from; identity is `(conversationId, index)`, and the stored shapes are structural mirrors in `$lib/types` rather than imports, because `types.ts` is dependency-free and this module imports it. **The pages own every write**, exactly as `src/routes/read/` does. It reuses the assistant's `ToolContext`, `executeToolCall` and `add_words` **verbatim** and imports nothing from `$lib/db`; `add_words` is the *only* tool exposed (`list_words` would be a paid round trip for a list already in the prompt, and a role-play teacher has no business deleting vocabulary), and it is called only for a word the *learner* produced correctly. Two envelopes are pinned with `responseFormat` and re-parsed with zod (`schemas.ts`, `.nullish()` normalized to absent): the one-off scenario call (`scenario.ts` — setting/roles in the native language, so the setup is understood before immersion starts) and the per-turn teacher reply (`teacher.ts`). **Corrections never enter the spoken line**: `correction.corrected` is the learner's whole message rewritten — a `{text, reading}` line, not a string — and `diff.ts` derives the inline spans by aligning it against what was typed. **The diff's unit is what the script delimits**: whitespace splits words only where the writing system spaces them, so `tokens` cuts Han, kana and the mainland South-East Asian scripts one character at a time (Hangul excluded — Korean spaces its words), and `spanGap` joins spans back by the same rule rather than letting the template's whitespace insert spaces the script does not have. **A learner with no keyboard for the target script types the reading**, so romanized input is declared legitimate in the prompt, `alignedForm` diffs against `corrected.reading` rather than the script when what they typed is Latin, and that comparison alone is loosened — tone marks folded, case ignored, and syllable spacing ignored as a whole-message test (`sameRomanization`), so a message that was right but spaced differently draws no correction. **The loosening is scoped to the reading and must stay there**: in the language's own spelling every mark counts, and French `ecole` for `école` *is* the correction. **The script is not a reward for getting it wrong**: the envelope also carries `heard` — the learner's own message written properly in the target script, asked for whenever any part of what they typed was not — so a correct romanized message still gets the sentence and its speaker button under the bubble. `runTurn` keeps the two exclusive: a surviving correction already carries that sentence, and a "correction" that corrected nothing (`isNoOpCorrection`) donates its `corrected` line to `heard` rather than being discarded with it. `teacher.ts` mirrors `chat.ts` — atomic turn, tool failures fed back as `{error}`, only `LlmError` escapes — with two deliberate differences: `MAX_TOOL_ROUNDS = 2` **and the last round is asked without `tools`** — one tool needs no read-then-write, and a model that spends the final round on a tool call would end the turn with a tool result nobody asked about and no line for the learner; and history replays as *dialogue*, learner turns as what was actually typed rather than the corrected version. A turn that will not parse degrades to prose rather than breaking the conversation; a scene that will not parse throws, because there is nothing to play without roles. Design doc: `docs/conversation-mode.md`.
