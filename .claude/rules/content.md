# Romanization and speech

- `src/lib/romanize/` — **local, per-language romanization, no LLM**. The registry (`index.ts`) is keyed by BCP-47 primary subtag (resolved from the free-text `targetLanguage` via `$lib/tts/languages`' `bcp47For`; currently `zh` only — Cantonese maps to `yue` and is deliberately excluded, jyutping ≠ pinyin). `loadRomanizer` dynamic-imports the implementation so pinyin-pro's ~287KB dictionary is a lazy chunk only Chinese learners fetch; `romanizerFor` is the sync accessor once loaded. `zh.ts`'s correctness invariant: the **whole string** goes through pinyin-pro and readings are sliced per char — context is what resolves polyphones (银行 háng vs 自行车 xíng), so never romanize a term in isolation. `tokenize(text, terms)` groups characters around the learner's vocabulary `terms` so a tracked word comes back as one token whose `text` equals its item term. Consumption: `planReadings` (`$lib/session/romanization`, rolled once at serve) yields a `ReadingPlan` — `sentence` for flat stored readings, `byTerm` for per-word adaptive fading — and `rubyFor` in `$lib/challenges/props` is the one composition every challenge component calls; `$lib/ui/RubyText.svelte` renders the tokens and stays dumb (hidden readings arrive already nulled by `applyPlan`). A `null` tokenizer (no local romanizer, or its chunk not landed yet) falls every slot back to the stored LLM `…Romanization` strings gated by `readings.sentence` — exactly the pre-ruby behavior, which is why the wire format keeps emitting readings: they are the fallback for every other language and feed the romanized `acceptedAnswers`. **A word on its own** (the garden, `/words`) goes through `itemReadingTokens` (`item.ts`) instead — **always shown, whatever the romanization preference says**: that preference fades a crutch during play, while a reference list states a fact about the word — and there the **stored `romanization` is authoritative**: it is the only thing that tells two same-spelled cards apart, so the local romanizer may split an *agreeing* reading per character with tone marks (`readingFold` decides agreement) but a disagreeing one is shown as stored, over the whole term. The one sanctioned isolation call is `Romanizer.unambiguousReading` (zh: multi-character terms via the word dictionary, single characters only when pinyin-pro lists one reading); `localReadings` uses it to backfill missing readings for free and leaves every polyphone for the model (`fillRomanizations`), which is the `readings` task's local-first, model-second order (`$lib/tasks/kinds/readings.ts` — the settings page works out the two lists for its own copy and starts the task; the def owns the writes and the one call, free readings landing before the model is asked). The voice model download is the `tts-model` task in the same way, wrapping `preloadKokoro` unchanged.

- `src/lib/tts/` — public API `speak(text, lang)`; zh+en use Kokoro v1.1 via sherpa-onnx WASM, everything else Web Speech. **The worker is plain JS at `static/tts/sherpa-worker.js`, deliberately outside Vite** (a bundled TS worker diverged between dev and build); config reaches it via the init message from `sherpa.ts`, with `models.ts` the single source of truth for artifact URLs/sizes. Model files (~439MB fp32) are runtime-fetched from a pinned mirror commit and cached in Cache Storage; the int8 variant is a known upstream NaN/silence bug — don't "optimize" back to it. Audio failures must degrade silently to fallback; sound never blocks gameplay.

- `src/lib/asr/` — dictation, `speak`'s mirror: public API `listen(lang, handlers)` behind the same `bcp47For` routing, one backend today (Web Speech, `webspeech.ts`). **The transcript lands in the composer, never in the send** — `appendDictation` splices it into the page's `input` and the learner presses Send, so a misheard word is a typo they fix rather than a mistake the teacher corrects them for, and `conversation/diff.ts` keeps aligning against a message they endorsed. That is what makes ASR's habit of silently repairing homophones harmless here, and it is the invariant to preserve: no path may send a transcript unread. The join is `spanGap`'s, borrowed from `conversation/diff` rather than re-derived, because a dictated 我想要 sits flush and a dictated `please` does not. Unlike synthesis, **recognition is not universal** (no Firefox), so `dictationAvailable()` gates whether the control renders at all — the fallback is typing, not another engine. `listen` returning `undefined` means no handler will ever fire; a returned session always ends in exactly one `onEnd`. `no-speech` and `aborted` are ordinary stops and must stay silent (`micErrorMessage`) — only a microphone the learner can still fix earns UI.
